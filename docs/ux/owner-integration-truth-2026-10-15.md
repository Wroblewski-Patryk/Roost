## Implemented read and interpretation

`GET /v1/connection/integration-status` composes a repeatable-read snapshot for the authenticated human's workspace. It returns exactly the ClickUp and Google Drive setting state, safe credential presence (without secret/config contents), latest selected sync event and latest success, and a separately named ToolAdapter catalog summary. The endpoint is read-only; API keys and task-scoped humans cannot use it. Technology uses that projection and links each provider to its exact Workspace Settings row. Settings describes stored credentials as unverified and distinguishes configured/enabled, configured/disabled, incomplete, absent and read-unknown states.

The latest recorded success is *recent evidence* only within 24 hours and only when it postdates the current setting update. Older success or success before a setting change is stale. A later selected failure is reported as the latest failed observation while the last success remains visible. No event is unknown. The selected families are ClickUp `sync_succeeded`/`sync_failed` and Drive import/changes success plus maintenance/content-refresh failure; this is a bounded observation, not a complete provider health or identity check. ToolAdapter status is explicitly catalog metadata and cannot override the provider setting or prove authorization.

Local native proof on a disposable, fully migrated database passed 5 nested cases: empty/unknown and no adapter; active stored configuration despite disconnected catalog; recent/stale/success-before-change/latest-failed observation; incomplete Drive credentials and disabled ClickUp setting; secret omission, workspace isolation, member access and API-key/task-scoped denial.
