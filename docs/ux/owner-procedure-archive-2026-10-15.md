# Procedure archive correction, 2026-10-15

This bounded Outcome 0 slice gives the workspace owner a guarded way to archive one procedure version after its active dependencies cease. It does not archive any production procedure. The ordinary procedure API and application agent context omit archived versions; exact GET and the console's explicit All history retain them. This does not complete RF-UX-012 or the procedure launch journey in RF-CTX-029.

## Runtime contract

- `GET /v1/process-core/procedures/:id/archive-preview` returns the exact version, short-lived signed digest, affected steps, valid contract IDs/source versions, stage and pipeline runs, policies, application/capability links, task admission and composition references, active executions, and protected-checklist status. It identifies blockers. The preview is a review snapshot, not an owner reauthentication credential.
- `POST /v1/process-core/procedures/:id/actions/archive` requires the same workspace owner, preview token, one-use request ID and reason. It locks owner membership, the existing Ready-source fence and procedure in consistent order, then rechecks the full impact under one serializable transaction. A changed dependency, active binding, protected checklist, expired token or replayed request with different content fails closed. Status, compact audit receipt and event commit together. An exact retry returns the prior receipt. The older workflow-definition procedure archive path delegates to this command.
- Native guards stop a new active stage, stage run, policy, required application/capability link, task admission or composition binding to a non-active procedure. Historical optional links remain; the ordinary agent packet excludes an archived procedure. A stage start against one returns `inactive_procedure` rather than starting work.
- The console's PL/EN dialog shows the exact preview identity, impact and blockers, requires a reason and acknowledgement, and forces refresh on stale or conflicted state. Only the workspace owner can open it. Retired versions remain eligible for archive when dependencies permit; archived versions remain in explicit history.

## Authority and limits

This is an owner-only status transition with preserved history and no deletion, provider effect, release authority or production business-record operation in this gate. It is governed by the five-minute signed impact preview and transactional recheck. The existing 90-second password reauthentication mechanism is reserved for separately classified sensitive commands and is not claimed here. RF-SEC-007 independent review was performed for the changed authority and data safeguards. Production business archiving requires the owner to review that record's live preview in a separate action.
