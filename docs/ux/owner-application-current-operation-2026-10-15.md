# Application current operation: bounded Outcome 0 slice

## Scope before edits, 2026-10-15

The accepted RF-UX-010/012 and RF-APP-003/014 require a truthful current application action, separate history, accountable actor and evidence without implying product or sale readiness. The production UI audit recorded an archived delivery Task as the nearest result. The current projection selects `outcomes[0]` when no open Task exists, while the service loads terminal Tasks alongside open ones.

This slice will select current Tasks only from `todo`, `in_progress` and `blocked`; show a clear empty state otherwise; and place terminal Tasks with their known execution/review state in linked history. It will preserve pending/deferred Decisions from canonical state, without title-based closure guesses, and explain the basis and limits of capability percentages in PL/EN. Existing workspace/application scope, owner API and record links remain the authority boundary. No company record changes, Worker/model call, portfolio application work, cleanup or new architecture are in scope.

Estimate: 8–16 hours of technical work, no paid model calls, at most one standard deployment after read-only preflight. Proof requires focused native/API cases, PL/EN responsive and keyboard UI, independent UX/Security review, `npm run validate`, `npm run codex:check`, scoped diff, exact-build deployment and read-only smoke. Signed-in production UI is claimed only if a session is available.

## Local implementation and proof

The operation projection now selects a nearest Task only from `todo`, `in_progress` or `blocked`. An open review helper remains visible when its accepted target is terminal. The API returns bounded terminal Task history with known execution and current-review status, exact Task links and a reason for the chosen current Task. A scope moved to another application leaves the former application. The Decision query uses the latest persisted revision and canonical state; it does not infer authority or closure from titles or age. The UI shows a true empty current state, a separate history disclosure, an exact return to this application, and PL/EN explanations that the 60/25/15 capability score is not product or sale readiness. Truncated history is explicitly marked incomplete.

The focused pure-model/navigation/render cases passed 41/41, covering terminal status, pending/deferred Decision preservation, open helper with terminal target, exact return validation, localized unknown and truncated states. The disposable PostgreSQL native API/browser case passed 1/1 after all 158 migrations, covering current/history and cross-application scope, exact API read, PL/EN at 390, 834 and 1280 CSS pixels, keyboard history open and return, empty and error states. G21 regressions passed 2/2, including a current Task after 101 newer scope revisions, moved application scope and a pending Decision. Synthetic full-page screenshots were inspected for mobile history and desktop current state; labels, action hierarchy and scope caveat are readable. This is fixture evidence, not production owner acceptance. Independent UX and Security read-only reviews identified the missing exact return, truncated copy, open-helper selection and an SQL column error; these were repaired and re-reviewed with no remaining concrete P0/P1. Security noted that separate read queries can briefly reflect different instants under a concurrent scope move; no such race was claimed tested.
