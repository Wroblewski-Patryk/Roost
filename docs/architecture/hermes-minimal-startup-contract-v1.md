# Hermes public minimal startup contract v1

RF-RUNTIME-005B6, 2026-09-16. **NOT_SUPPORTED for the strict minimal-startup contract on the inspected pin.** Source analysis is complete; implementation and execution are not authorized by this result. The selected public interface remains the standard `chat --oneshot --quiet --query-file -` CLI. It supports sealed stdin and explicit model/provider/reasoning/toolsets, but still schedules bundled-skills synchronization and banner prefetch before the quiet execution branch. No reviewed public switch suppresses that startup bundle while retaining this command and the sealed profile.

This is a specific limitation, not a claim that Hermes cannot run coding tasks. Plugin/MCP/hook suppression has a public control; empty toolsets and provider fallback now have a more precise contract below. The [B5 negative qualification](hermes-effective-config-qualification-v1.md) remains negative, `hermes_sealed_config_enforcement_unproven` remains mandatory, and all six gates remain false. [B4 owner attestation](hermes-same-owner-profile-v1.md), including its accepted residual risks, is unchanged.

## Selected public command/config contract

The sole candidate is the following **non-executable template**, pending qualification; placeholders are not actual model choices or authority:

```text
hermes chat --cli --oneshot --quiet --query-file -
  --provider openai-codex --model <approved-canonical-model>
  --reasoning <approved-reasoning> --toolsets <approved-built-in-toolsets>
```

Worker would construct an argv array, never a shell command, using the sealed task packet. The model and reasoning are exact approved values. Toolsets are a nonempty task-specific subset of the reviewed built-in mapping; for ordinary coding the proposed expansion ceiling is `file,terminal`, with terminal omitted unless needed and authorized. Expanding to browser, web, skills, MCP or delegation needs a separately reviewed task/tool contract. Unknown values fail at Worker admission even though chat itself merely warns about unknown toolsets.

Public environment `HERMES_SAFE_MODE=1` suppresses plugin/MCP/hook customization while retaining the private configuration; unlike `--safe-mode`, it does not itself set `HERMES_IGNORE_USER_CONFIG` or `HERMES_IGNORE_RULES`. Those bypass flags are not selected. This distinction is documented in the pinned public environment reference and implemented by [hermes_cli/main.py](https://github.com/NousResearch/hermes-agent/blob/939e45c91d751fadd94dcd1b873ac3cb44846213/hermes_cli/main.py#L2853-L2863). Effective dotenv/environment precedence still must be qualified before relying on it.

Retain the B3 disabled consumers, exact private home/config binding and B4 owner attestation. A later, separately authorized profile revision would make both fallback forms empty, aliases/custom routing absent, worktree false and task tools explicit, and would bind all relevant environment/overlay inputs. Do not add guessed switches. `providers: {}` alone neither disables built-in providers nor proves an effective route.

The top-level `-z PROMPT` path is rejected for this contract: [hermes_cli/main.py](https://github.com/NousResearch/hermes-agent/blob/939e45c91d751fadd94dcd1b873ac3cb44846213/hermes_cli/main.py#L2914-L2933) passes the argument as prompt, whereas stdin query-file handling belongs to chat; [hermes_cli/oneshot.py](https://github.com/NousResearch/hermes-agent/blob/939e45c91d751fadd94dcd1b873ac3cb44846213/hermes_cli/oneshot.py#L184-L207) also enables YOLO and hook auto-accept. It is not a drop-in sealed-stdin route. No private Python entrypoint, monkeypatch, production audit-hook wrapper or fork is selected.

## Fallback, authentication and evidence boundary

For this candidate, the complete route checklist is: startup alias/MoA expansion; configured/custom/local endpoint resolution; `auto` provider ladder; CLI AuthError fallback; agent initialization fallback; in-turn fallback chain; credential-pool selection/rotation; auxiliary model consumers; resumed-session and Kanban routes. The selected command excludes resume/Kanban and the proposed profile/argv checks exclude alternative providers/models. The exact primary route and reasoning still need qualification: a command string is not an effective-runtime receipt.

A single pool entry plus no provider fallback is sufficient only for the narrow statement “this fixed eligible pool has no other entry to select.” It does not prove that account cannot change over the attempt. [load_pool](https://github.com/NousResearch/hermes-agent/blob/939e45c91d751fadd94dcd1b873ac3cb44846213/agent/credential_pool.py#L2715-L2787) can heal/seed/persist; [refresh/import](https://github.com/NousResearch/hermes-agent/blob/939e45c91d751fadd94dcd1b873ac3cb44846213/hermes_cli/auth_codex.py#L359-L405) can recover from the current Codex CLI source. Refresh-token renewal for the approved owner is distinct from prohibited switching to another account. These facts do not invalidate B4: silent account changes and unreported session loss are explicitly accepted residual risks of owner-attestation-only qualification, not newly required technical fingerprint checks.

The existing public `hermes auth list openai-codex` surface reports count, label, type, id, priority and state ([hermes_cli/auth_commands.py](https://github.com/NousResearch/hermes-agent/blob/939e45c91d751fadd94dcd1b873ac3cb44846213/hermes_cli/auth_commands.py#L434-L468)). Labels can derive from email/username claims ([agent/credential_pool.py](https://github.com/NousResearch/hermes-agent/blob/939e45c91d751fadd94dcd1b873ac3cb44846213/agent/credential_pool.py#L297-L303)); output is not qualified as nonsensitive. No public count/type-only JSON surface was established. A future separately authorized local operator inspection could retain only count/type booleans, never raw labels, identifiers or auth output. This atom did not execute it, and owner attestation remains the current accepted auth authority.

A future fail-closed admission receipt must bind pin/source qualification, profile/config digest, relevant effective environment/overlay policy, canonical provider/model/reasoning, exact expanded tool names, fallback/background categories, Ready version/expiry, native Job proof and B4 attestation reference. It must not contain secrets, account identifiers, raw config or CLI output. Missing/unknown/drifted/expired proof blocks before spawn. The quiet final response cannot issue such a receipt; retrospective detection cannot prevent a first unauthorized call. No successful issuer or production runtime introspection is implemented here.
