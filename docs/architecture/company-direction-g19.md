# G19 company direction

## Commissioned boundary

The owner approved one installation-private, versioned strategic purpose; a separate impact preview and adoption; one aligned task and one conflicting decision with evidence or an owner-resolved exception; current adopted purpose only in task-bound agent API/MCP and native execution packets. G19 includes an additive migration, PL/EN owner console, isolated verification, independent Security review and ordinary release after preflight. Production smoke is read-only. No real company-purpose text is authorized for production creation or adoption by this gate. Numeric targets and autonomous prospecting remain separate.

## Data and authority

`company_direction_versions` retains immutable text/provenance once a draft is adopted, monotonically numbered per workspace. `company_direction_heads` points to the single current adopted version. Drafts and superseded versions remain owner-visible for audit and never enter agent reads or packets. The owner creates a draft, receives a bounded preview of all non-archived goals, projects, tasks and decisions plus active procedures, and confirms adoption separately. The preview is a 15-minute, one-use server receipt bound to the exact owner, workspace, draft, current head and digest of affected IDs and revisions. Adoption re-computes the snapshot in one Serializable transaction and rejects stale scope or head.

Comparisons bind an exact task or decision revision and current direction version to a proposed outcome, evidence and owner assessment. Confirmation of alignment or a conflicting exception requires fresh owner action proof. A later subject edit, new governance impact preview or direction adoption makes the comparison historical. When a current direction exists, governed decision acceptance requires a resolved comparison bound to the current decision impact preview; an aligned confirmation or accepted exception admits that check, while a rejection does not. Existing decision authority, risk, grant and impact checks still apply. Workspaces with no adopted direction retain the prior governance path.

The task-bound agent GET locks a live bound credential, active agent, workspace and exact assigned task in `todo` or `in_progress`. It returns only the current adopted direction. The MCP manifest advertises this exact read surface to bound agents. The sealed execution packet and Ready revision include the same current version; validator checks packet/context identity and workspace. Source watches cover the head and, after an adoption, its version. Their triggers invalidate Ready and signal active context stop when direction changes. Migration preserves pre-G19 Ready pins while no direction exists. The first adoption invalidates every remaining Ready pin in that workspace, including older pins without new-table watches.

## Proof and limits

Isolated API and browser tests use fictional purpose text and records. They do not establish that the owner has chosen a real purpose. The impact preview describes affected record counts and likely review work; it does not auto-edit linked records. A comparison is an explicit human assessment, not a model-calculated truth judgment. Provider tokens and cost are not involved in G19 proof.
