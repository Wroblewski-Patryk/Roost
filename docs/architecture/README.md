# Architecture documentation

This folder is the canonical record of Roost's system boundaries, data
ownership, module contracts, deployment shape and accepted technical choices.

## Reading order

1. `architecture-source-of-truth.md`
2. `system-architecture.md`
3. `tech-stack.md`
4. `organizational-architecture-bridge.md`
5. `unified-organizational-operating-system.md`
6. `companycore-business-module-map.md`
7. `process-core-workflow-core-architecture.md`
8. `department-management-systems-architecture.md`

Architecture decisions belong here or in `docs/decisions/`. Execution plans,
generated reports, task histories and agent memory do not.

Keep architecture documents aligned with code whenever module boundaries,
data ownership, API contracts or deployment topology change.
