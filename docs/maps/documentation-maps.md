# Documentation Maps

Last updated: YYYY-MM-DD

## Purpose

This folder contains navigation maps, not detailed project truth.

Maps answer "where should I look first?" They should point to canonical docs,
state files, registries, pipelines, and historical evidence without duplicating
their content.

## Maps

| Map | Use |
| --- | --- |
| `product-map.md` | Product intent, value, scope, and open product decisions. |
| `architecture-map.md` | Architecture truth, graph records, modules, and runtime contracts. |
| `release-ops-map.md` | Deploy, smoke, rollback, release, and operator evidence. |
| `agent-work-map.md` | Agent startup, current state, proof lookup, and handoff paths. |
| `documentation-maps.md` | This guide. |

## Rule

If a map starts accumulating implementation detail, move that detail into the
semantic owner doc and keep the map as a pointer.
